## 🎯 על הפרויקט

**GymSystem** היא מערכת לניהול חדר כושר, המפותחת במסגרת פרויקט קבוצתי.

המערכת נועדה לרכז ולנהל את הפעילות השוטפת של חדר הכושר, תוך עבודה מסודרת לפי דרישות, עיצוב טכני ותהליך פיתוח צוותי.

הפרויקט מחולק למשימות קטנות וברורות, כך שכל חבר צוות יכול להתמקד בחלק שלו ולדעת בדיוק מה עליו לבצע.

> 🚀 **לא צריך לבנות הכול בבת אחת. מתחילים במשימה שלך — ומשם מתקדמים.**


# 🌿 עבודה עם Branches

### ⚠️ כלל חשוב

> ❌ **לא עובדים ישירות על `master`.**

העבודה מתבצעת דרך Branch מתאים.

לדוגמה:

```text
master
│
└── develop
    │
    ├── netanel/appointments
    ├── member-name/task
    └── member-name/task
```

### 🏠 `master`

ה־Branch הראשי של הפרויקט.

מיועד לגרסה יציבה ומאוחדת של המערכת.

### 🔧 `develop`

ה־Branch המרכזי לפיתוח.

ממנו יוצאים ה־Branches של חברי הצוות.

### 👤 Branch אישי / משימתי

כל חבר צוות עובד על ה־Branch שהוגדר עבורו או עבור המשימה שלו.

לדוגמה:

```text
netanel/appointments
```

# 🚀 רוצה להתחיל לעבוד?

## זה כל מה שאתה צריך לעשות:

### 1️⃣ מצא את המשימה שלך ב־Jira

לדוגמה:

```text
REQ-XXX
```

בדוק מה בדיוק המשימה שלך ומה ה־Subtasks הקשורים אליה.

---

### 2️⃣ עבור ל־Confluence

קרא את החלק הרלוונטי במסמך העיצוב.

שים לב במיוחד ל:

* Classes
* Attributes
* Methods
* קשרים בין מחלקות
* דרישות מיוחדות
* Dependencies

---

### 3️⃣ עבור ל־Branch שלך

```bash
git checkout develop
```

לאחר מכן עבור ל־Branch שלך:

```bash
git checkout <your-branch>
```

---

### 4️⃣ מתחילים לכתוב קוד 💻

עובדים **רק על החלק של המשימה שלך**.

לא צריך לפתור עכשיו את כל המערכת.

> 🎯 **משימה אחת בכל פעם.**

---

### 5️⃣ בדוק שהקוד עובד 🧪

לפני Commit:

* ודא שהקוד מתקמפל.
* בדוק את הפונקציונליות שהוספת.
* ודא שלא שברת חלק אחר במערכת.

---

### 6️⃣ Commit 📝

כתוב Commit ברור שמתאר מה עשית.

לדוגמה:

```bash
git add .
git commit -m "Implement appointment management"
```

---

### 7️⃣ Push ⬆️

```bash
git push
```

---

### 8️⃣ Pull Request 🔀

לאחר שסיימת:

```text
Branch שלך
     ↓
Pull Request
     ↓
Code Review
     ↓
Merge
```

אל תעשה Merge לבד אם העבודה דורשת Review של חבר צוות.

# 📌 כללי עבודה

### 1. 🛑 לא משנים דברים של אחרים בלי תיאום

אם משהו בקוד של חבר צוות משפיע על המשימה שלך — מדברים לפני שמשנים.

### 2. 🌿 לא עובדים על `master`

הפיתוח מתבצע דרך ה־Branches שהוגדרו.

### 3. 📝 Commit ברור

Commit צריך להסביר בקצרה מה השתנה.

### 4. 🧪 בודקים לפני Push

אל תשלחו קוד שלא בדקתם.

### 5. 🔀 Pull Request לפני Merge

כל שינוי משמעותי עובר דרך התהליך שהוגדר לצוות.

### 6. 💬 אם משהו לא ברור — שואלים

עדיף לשאול שאלה של דקה מאשר לתקן טעות של שעה.
